# SentinelGate AI Security Gateway — Documentation Portfolio Project

## About this project

This is a fictional documentation site built to demonstrate end-to-end technical writing for a developer- and administrator-facing product: an AI security gateway that sits between applications and AI providers, applying security policies and logging events.

**SentinelGate is not a real product.** It was created solely to showcase documentation structure, writing, and API reference conventions for products in this space. No content here reflects a real company, codebase, or production system.

## Why this project

Most of my professional experience is in content QA, editorial review, and structured authoring rather than authoring product/API documentation from scratch. I built this project to demonstrate that I can:

- Design an information architecture for a multi-audience product (developers, admins, support)
- Write a REST API reference from an endpoint specification, including request/response examples and status-code handling
- Document configuration using structured formats (YAML) with inline explanation
- Write procedural content (quickstart, admin workflows, troubleshooting) aimed at different technical skill levels
- Apply a documented, repeatable process for using AI tools in a documentation workflow — drafting, validating, and QA'ing content before publication, rather than publishing AI output unreviewed

## What's included

| Section | Demonstrates |
|---|---|
| **Overview** | Scoping and audience definition for a technical product |
| **Quickstart** | Task-based procedural writing for first-time setup |
| **Administrator Guide** | Workflow documentation for a non-developer technical audience |
| **API Reference** | Endpoint documentation, request/response examples, status-code table |
| **Configuration Reference** | Structured config documentation (YAML) with field-level explanation |
| **Troubleshooting** | Symptom-based, scannable problem/solution structure |
| **Release Notes** | Standard new/improvements/breaking-changes format |
| **AI-Assisted Documentation Workflow** | A defined process for using AI tools responsibly in documentation — sourcing from specs, drafting, technical validation, SME review, and QA before publishing |

## Tools & approach

Built as a static HTML site to keep the project self-contained and easy to review. The structure mirrors a typical docs-as-code site (versionable, single-source content, section-based navigation) even though this instance isn't wired to a live publishing pipeline.

## Note

This project intentionally does not claim real hands-on experience with a security product, a live API, or a production docs-as-code pipeline (Git-based CI publishing, static site generators). It's meant to demonstrate documentation craft and structure that would transfer to that context, not to overstate direct experience.
