Overview

SentinelGate is a fictional enterprise platform created for this portfolio project to demonstrate product, administrator, and API documentation for an AI-security product.

The gateway sits between an application and an AI provider. It applies configurable security policies, routes requests, and records security events for operational review.

Audience

Application developers, platform administrators, product teams, and support engineers.

Quickstart: Configure a Gateway

Use this procedure to configure a development gateway and send a test request.

  1. Sign in.
  2. Open AI Gateways and select Create gateway.
  3. Enter the provider endpoint and authentication method.
  4. Save and confirm Connected.
  5. Create an API key with Gateway invoke scope.
  6. Send a test request.

Verify

Confirm an HTTP 200 response. If blocked, review the security policy and event log.

Administrator Guide: Configure a Security Policy

Security policies determine how SentinelGate evaluates requests before forwarding them to an AI provider.

  1. Open Security Policies.
  2. Create or open a policy.
  3. Enable prompt-injection protection and sensitive-data detection.
  4. Select the action for blocked requests.
  5. Save the policy.

Use metadata-only logging when request content must not be retained.

API Reference

This example shows a simplified REST endpoint for invoking a configured AI gateway.

POST /v1/gateways/{gatewayId}/responses

Send input to a configured gateway.

POST /v1/gateways/gw_123/responses
Authorization: Bearer <API_KEY>
Content-Type: application/json

{"input":"Summarise the deployment steps."}

Configuration Reference

The following YAML illustrates a gateway configuration.

gateway:
  name: customer-support-gateway
  provider:
    endpoint: https://api.example-llm.com/v1
  security:
    promptInjection: true
    sensitiveDataDetection: true
  logging:
    mode: metadata-only

Troubleshooting

Use these checks for common gateway and API issues.

Not connected

  • Verify endpoint.
  • Confirm credentials.
  • Check network access.
  • Review event logs.

401 Unauthorized

Verify that the API key is active and sent in the Authorization header.

429 Too Many Requests

Reduce request frequency and use exponential backoff.
